01

把“分割”改写成两条曲线。

这个项目要回答的是：在图像的每一列，真皮层在哪里结束，脂肪层又在哪里结束？

灰度超声图中的层状结构可以用两条大体沿水平方向延伸的线来表达。普通语义分割会给每个像素分配类别，输出一张区域掩码；这里选择更紧凑的表示：对每条边界、每一个横坐标 x，预测纵坐标 y。这样一幅 256×256 图像的最终输出只有 2×256 个坐标。网络内部仍产生二维热图，用它来帮助模型寻找边界的位置。

I ∈ ℝB×1×H×W → Z ∈ ℝB×L×H×W → ŷ ∈ ℝB×L×WB：批大小；L：边界条数，本任务为 2；H：图像高度；W：图像宽度；Z 是未归一化分数（logits）。

标签顺序在 TARGET_LABELS 中写死为「真皮层下界」「脂肪层下界」，因此第 0 个通道应该在第 1 个通道上方。图像坐标的 y 轴向下增长，合理的顺序是 y₀(x) ≤ y₁(x)。两条线之间可以构造区域掩码 M(y,x)=1[y₀(x)≤y≤y₁(x)]；厚度可写为 d(x)=y₁(x)−y₀(x)。这两个式子是后续应用推导，当前训练源码没有输出区域掩码，也没有计算毫米厚度。

这种表示依赖“每条线在每列至多一个 y”的假设。若结构出现竖直边界、折返、多个不连通层，同一列一个数就不够表达。模型也始终输出每一列的位置，没有独立的边界存在性头；缺少标注的列只能通过有效性掩码排除监督。

02

数据的契约，比模型名字更重要。

数据目录里，images/ 与 annotations/ 相邻出现。扫描函数递归寻找图像及同名 JSON，过滤缺少目标标签的标注。读取时只保留指定两条线；重复标签取第一个有数据的对象，其他皮肤标签不参与本任务。标注点经过有限值、图像范围检查，横坐标四舍五入为整数。同一列存在多个 y 时取均值。

坐标与有效性分开存

y_px[L,W] 保存浮点纵坐标；valid[L,W] 保存布尔值。没有标注的列初始化为 0，但这个 0 不能当成“边界在图顶端”。只有 valid=True 时，它才是一个可靠监督点。丢掉掩码相当于给不存在的标签强行补零。

重采样不是只缩放 y

宽度改变后，目标图每一列都要查询原图位置，再对已知点做一维插值；高度改变后，y 还要乘高度比例。代码在多个已知点的首末区间内全部标为有效，因此会填补中间缺口；只有一个已知点时，实际将整幅宽度置为有效，这是需要警惕的实现选择。

sx=W′/W，sy=H′/H； xquery=x′/sx； y′(x′)=interp(xquery; xknown,yknown)·sy例：高度 594→256，原 y=200 对应约 86.2。参数尺寸是 (W,H)，张量末两维却是 (H,W)。

03

让图像变化，让几何关系保持一致。

训练脚本设置 LINEDET_UNIFY_MODE=unify 和 LINEDET_UNIFY_SIZE=516,594。这里 516×594 代表统一裁剪的参考比例，网络真正接收的尺寸仍由 --img_size 256 决定。unify 保留原图，并为足够高的图像追加裁剪副本：裁剪高度 hc=floor(w×594/516)，从底部裁掉多余部分；如果任一目标线裁完后完全没有有效点，就不追加副本。这个逻辑也会作用于验证集。

例如 422×728 的图像会尝试裁成 422×485。原图版本和裁剪版本都各自拉伸到 256×256，标注跟随各自几何变换。因此 unify 是“样本扩充 + 两种视野”，并不是把所有图先变成 516×594。目录中的源图不被改写。none/crop/resize/unify 四种模式不可混为一谈，环境变量在模块导入时读取。

增强分成外观与几何两类

噪声、模糊、亮度、对比度、低分辨率模拟、Gamma 改变外观，一般不改边界坐标；左右翻转、平移和特殊纵向变形改变空间位置，必须同步改 y 与 valid。每个训练样本在标准化前有 20% 概率执行特殊外观增强；联合增强后有 30% 概率随机选择一种特殊增强，包括纵向变形与浅部亮条纹。验证不做随机训练增强，但仍做标准化以及可能的 unify 扩充。

Inorm=(I−mean(I))/(std(I)+10−7)这是逐张图像的整体标准化；不是 ImageNet 的三通道固定均值方差归一化。
读懂真实实现，也要能看出错误

右侧擦除抽到 erase_width=0 时，Python 的 -0: 等于 0:，会擦掉整幅图；“向下平移”分支实际上仍 roll(-shift)，却清空顶部；特殊形变不接收 valid，也就无法同步更新掩码。几何增强必须同时验证图、坐标和有效范围，不能只看图片“像不像”。这些是现有代码问题，手册保留原码并解释，不暗中修改。

04

从局部纹理，走向边界位置。

MobileNetV3 提取特征，两种尺度进行融合，热图头为每条线生成位置分数。

浅层特征空间分辨率较高，保留局部纹理和边缘；深层特征视野更大，帮助区分组织层与噪声。把深层上采样到浅层尺寸，再沿通道拼接，卷积就能同时利用两者。这份类名虽然叫 LineCoordNetFPN，实现是一次双尺度拼接融合，不是完整的多层金字塔逐级相加结构。

第一步：可学习的去噪，而非固定滤镜

DenoiseBlock 使用 5×5 高斯核初始化卷积权重，sigma=1，padding=2，默认可训练。高斯核先归一化，使初始输出像邻域加权平均；随后梯度可以把它调整为任务需要的滤波器。训练后不保证它仍是高斯核，也不保证权重和为 1。groups=channels 表示每个输入通道独立滤波，本项目灰度输入只有 1 个通道。

第二步：理解 MobileNetV3 内部的基本积木

MobileNetV3 的倒残差块通常包含 1×1 通道扩张、逐通道空间卷积、可选的 SE 通道调节，再用 1×1 投影压缩；形状允许时加残差。逐通道卷积减少空间卷积的参数与计算，逐点卷积负责通道混合。ReLU 与 h-swish 提供非线性。此项目调用 torchvision 的现成网络，截取 features，并把第一层从三通道换成一通道卷积。官方实现可用于进一步手写这些库内模块。

结构依据：torchvision MobileNetV3 源码；设计背景：Searching for MobileNetV3。

第三步：沿通道拼接，再压缩

256×256 输入下，features[:5] 输出 [B,40,32,32]，其余 features 输出 [B,960,8,8]。插值把后者变为 [B,960,32,32]，cat(dim=1) 得到 1000 通道，3×3 卷积压到 40 通道。热图头执行 40→128 的 3×3 卷积和 128→2 的 1×1 卷积，最后双线性插值回 256×256。这些尺寸依据源码与默认 MobileNetV3 结构静态推导，未在本次制作中重新运行训练。

卷积尺寸遵循 Hout=floor((H+2p−d(k−1)−1)/s+1)。例如 k=3、p=1、s=1 时高宽不变；stride=2 通常近似减半。1×1 卷积在每个空间位置对通道做线性组合，所以可以把 128 个描述特征投影为两条边界各自的 logit。Conv2d 参数说明。

一个参数，要追到它真正被使用的地方

main.py 虽然解析 --backbone_pretrained，但构造模型时没有传进去，所以实际仍按默认 pretrained=False 初始化。直接调用 build_backbone(pretrained=True) 时，替换的首层仍是新初始化权重。V4 分支依赖 timm，用 features_only 返回两个尺度，其通道来自 feature_info，不能照搬上图的 V3 数字。

↗ 完整网络 / forward
05

让“找最高点”成为可导的计算。

固定一个样本、一条线和一列 x，网络给 H 个纵向像素各一个分数 zy。直接 argmax 只能选一个整数索引，很难把坐标误差的梯度传回分数。Soft-argmax 先用 softmax 把这一列变成概率分布，再对高度求加权平均。它输出的是连续坐标，可以处在两个像素之间。

py=exp((zy−max(z))/T) / ∑j=0H−1 exp((zj−max(z))/T)
ŷ=∑y=0H−1 y·py， ∂ŷ/∂zk=pk(k−ŷ)/T本实现 T=1；沿 dim=2（高度）归一化。减去最大值不改变概率，可以减少指数溢出。

当概率集中在 80 与 81 两行，期望可能是 80.3。分布很平时，预测靠近图像中部；若存在两个峰，期望可能落在两峰之间，那里不一定是真实边界。温度小会使分布更尖，但训练中的梯度也可能更容易饱和。只改变一个位置的分数会影响整列归一化后的概率，这正是可导坐标与热图间的联系。

动手观察 / 一列像素怎样变成一个坐标

以下使用 32 行的双峰合成分数，演示原理；不是模型实际输出。

绿色柱：每行概率；黄色竖线：概率加权平均。两个峰的概率质量接近时，期望会落在两峰之间；即使两峰相距很远也会如此。

监督热图：给正确坐标周围也留一点余地

损失内部根据真实坐标构造高斯目标，接近真实边界的像素得到更高值，距离越远值越小，再沿高度归一化。valid=False 的列整列置零，损失也排除它们。sigma 决定分布宽度，单位是网络输入分辨率下的像素。当前真正用于损失的 sigma 固定为 3，而非命令行默认的 2。

g(y;x)=m(x)·exp(−(y−ygt(x))²/(2σ²))
q(y;x)=g(y;x)/(∑jg(j;x)+ε)m 是有效列掩码。高斯提供“附近也接近正确”的连续监督，但边缘截断会使归一化分布不再完全对称。
自测：为什么不能写 softmax(dim=1)？

dim=1 是边界通道，会让同一像素上的两条线互相竞争；本任务需要每条线在同一列的所有高度之间竞争，因此用 dim=2。输出仍是 [B,L,H,W]，沿高度求和后才变为 [B,L,W]。

↗ soft_argmax / generate_gaussian_heatmap
06

一个目标负责定位，其他目标负责约束形状。

网络需要既准确又平滑，同时维持上下层次。代码把热图、坐标、拓扑、二阶平滑和一阶总变分组合成总损失。下面的系数是 当前类内部实际赋值，不是构造函数签名看起来给出的默认值。

ℒ = 1.0ℒheatmap + 0.1ℒcoord + 0.01ℒtopo + 0.1ℒsmooth + 0.05ℒtv
损失项计算与直观意义真实实现要点
坐标 MSE∑m(ŷ−y)² / ∑m。大偏差被平方放大。masked_select 只选有效列；单位是像素²。
热图 BCE−mean[q log s +(1−q) log(1−s)]，s=sigmoid(z)。逐像素拟合软目标。默认 bce；分母为有效列数×H。此处 sigmoid 与解码时 softmax 是两种不同的归一化。
拓扑mean ReLU(ŷl−ŷl+1+margin)。上界跑到下界下面就惩罚。margin 默认 0；软约束而非绝对禁止交叉；未使用 valid。
二阶平滑mean |ŷ(x−1)−2ŷ(x)+ŷ(x+1)|。减少曲率突然变化。线性斜坡为 0；宽度不足 3 返回 0；未使用 valid。
一阶 TVmean |ŷ(x+1)−ŷ(x)|。减少相邻跳动。倾斜直线仍有惩罚；宽度不足 2 返回 0；未使用 valid。

热图项约束“分数分布应该怎样”，坐标项约束“概率期望在哪里”，二者不是重复。BCE 把每个像素视作独立概率，而 Soft-argmax 沿列竞争；即使 sigmoid 分数拟合了高斯 q，softmax(z) 也不保证恰好等于 q。因此不能把网络返回的 heatmaps 直接叫作概率图。MSE 分支先对 logits 做高度 softmax 再和 q 比较，定义又不同。

以 [10,12,14] 为例，二阶差分是 10−24+14=0，TV 为 (2+2)/2=2。预测 [10,14,10] 时，二阶差分绝对值变成 8，明确惩罚突起。若上界 120、下界 100，拓扑项会产生 20 的违反量；上下界顺序正确则贡献 0。这些约束在没有标注的列仍然生效，可以平滑延伸，也可能掩盖真实的不确定性。

签名参数不等于生效参数

HeatmapCompositeLoss 中 lambda_topo=0.5、lambda_smooth=0.01、sigma=2.0 的传入值被内部常量覆盖。旧 CompositeLoss 的 lambda_coord 也没有乘到总损失上，DiceCELossFunc 只是一个空 nn.Module，实际不计算 Dice。false_region_smooth 定义了但当前训练没有调用。修改实验参数前必须追踪赋值与调用链。

↗ 每项损失的实现与练习
07

验证集必须回答“没见过的数据会怎样”。

一段视频或同一采集目录里的相邻帧往往高度相似。简单逐图随机划分可能让训练与验证共享近似内容。固定清单以同时包含 images/ 与 annotations/ 的父目录为组，整个组只能进一边。它实现的是目录级隔离，只有目录恰好对应独立受试者时才能据此声称受试者级隔离；源码没有检查患者身份。

choose_validation_groups 把每个组的图像数当作重量，寻找总数最接近 10% 目标的子集。它保存“可达总数→前驱总数与组名”，逐组更新并回溯选出验证组。对现有可达总数做快照，避免一次循环重复使用同一组。排序后用局部随机数生成器打乱，让相同 seed 得到一致的平局选择。它不是普通的逐图 train_test_split。

每行 JSONL 记录 split、group、image、annotation，路径相对 data_root。加载器核对根路径、文件存在性、组与图像标注对的交集。meta.json 记录清单摘要及计数；摘要依据条目和路径生成，不哈希每张图的内容，也不意味着加载时自动检查全部数据是否新增或替换。更换数据应重新生成并审查清单；不能把文件名相同当作数据没变。

train100 不是独立验证协议

不使用清单时，训练保留所有图，验证取扫描列表末尾约 10%。因此验证图已经参与训练。train90 才通过 manifest 使用互不重叠的目录组。固定 seed 减少随机差异，但不能修复验证集污染，也不保证跨设备或不同依赖版本逐位一致。

↗ 子集选择与清单生成↗ 加载与重叠检查
08

把一个批次走完，就读懂了训练的主干。

train减脂.sh 指定数据路径、unify 配置、MobileNetV3-Large、两条线、256 输入、100 epochs、batch size 48 和学习率 10⁻³；调用 run_dual_split.sh 顺序训练 train100 与 train90。后者保存代码和清单快照、种子与参数，整理日志，再汇总最优指标。脚本设置 set -euo pipefail，让未定义变量与管道失败更早暴露，但提示倒计时并不会自动确认清单已更新。

model.train() 使 BatchNorm 使用训练行为。每批先把 tensor 移到 device，再 zero_grad 清除上一批梯度；前向传播得到坐标与热图；loss.backward 通过计算图累积梯度；clip_grad_norm_(…,5.0) 限制梯度整体范数；AdamW 更新参数。AdamW 在自适应梯度更新之外做权重衰减，本代码 weight_decay=10⁻⁴，没有学习率调度器、混合精度或早停。不要从保存 best 的逻辑推断存在 early stopping。

DataLoader 中 shuffle 只对训练为 True；num_workers 控制取样子进程数；pin_memory 固定 CPU 内存便于设备传输；自定义 collate 组织字典。两个 torch.Generator 使用 seed 与 seed+1。训练平均损失按 batch 数平均，而不是对所有样本数加权，因此最后一个不足整批的 batch 会得到相同权重。

验证、保存、可视化各负责一件事

model.eval() 切换 BatchNorm 等模块行为，@torch.no_grad() 关闭梯度记录，两者互不替代。验证逐批记录损失、MAE、阈值准确率和距离指标，再 nanmean。MAE 更低就保存 best.pth，并 deepcopy 当前 state_dict 防止最优权重随继续训练变化；每 10 轮还保存一次普通 checkpoint。每轮从前 5 个验证 batch 各取第一张图绘制 GT/预测和热图。MLflow 记录被 try/except 包围，日志失败不会自动终止训练。

每批 loss_dict 中的 detach 只是为了记录标量时不再携带梯度图；总 loss 本身保留计算图，所以 backward 仍能工作。torch.save 保存字典里的权重、轮次与参数，不包含 optimizer.state_dict；因此现有 checkpoint 不足以精确恢复 AdamW 的动量状态。当前项目也未提供训练恢复入口。

两个不会真正控制流程的开关

--use_heatmap 使用 store_true 且默认 True，没有命令行方式关闭；模型 forward 又始终返回 (y_px, heatmaps)。直接把 args.use_heatmap 改成 False 不足以得到可用的坐标单输出分支。--skip_export 会跳过导出，也会跳过导出前的最优权重加载，最终 MLflow 注册的可能是最后一轮模型。

先看评价定义，再看小数点。

MAE 是有效列上的平均绝对坐标误差，单位为缩放后图像的像素。A@t 是误差不超过 t 像素的点所占百分比。训练优化的是包含平方项与正则项的总损失，选最优 checkpoint 用的是 MAE，两者变化趋势不必完全一致。

MAE=∑m·|ŷ−y| / ∑m； A@t=100·mean(1[|ŷ−y|≤t])上式 A@t 对应现有未加掩码实现；建议修正为只统计有效点。t 在代码中取 2、3、5。

一个很容易误读的 Hausdorff 实现

标准二维曲线距离应比较点 (x,y)。当前实现只构造 |pi−gj|，比较所有 y 值集合，忽略横坐标。预测 [0,10] 与真值 [10,0] 的 y 集合完全相同，当前 HD 会是 0，但对应列 MAE 为 10，两条二维线并未重合。HD95 是把双向最近差值合并后取 95% 分位数；这个“95”不能消除距离定义本身的问题。

评价结果的边界

A@t 和 HD/HD95 没有 valid 掩码；验证汇总按 batch 等权平均；unify 的同源裁剪副本会改变样本权重。要正式评价，应统一有效点规则，修正二维距离，按总有效点聚合，并另设未用于选模型的测试集。这里展示的是源码及其记录，不补造没有保存的独立测试结果。

训练结束以后，还有输入契约要对齐。

普通推理由 infer_lines 在 eval 和 no_grad 下调用模型，返回坐标与原始热图 logits。默认还对坐标沿宽度做核大小 5、sigma=1.5 的一维高斯平滑，端点采用复制填充；因此训练中展示的线可能经过平滑，而 eval 指标和端侧导出用的是未平滑坐标。模型没有输出有效性或置信掩码，infer_lines 也没有自动把 NumPy 输入移动到模型设备。可视化不能代替数值评价。

端侧导出额外加载一个独立训练的 MobileNetV3-Small 质量分类器：单通道输入，输出 bad/good 两类。它和边界网络被 ModelWithArgmax 包在一起，接收同一标准化输入。质量分类器不是此处训练的联合任务头，也不与边界模型共享骨干；训练代码只优化边界模型参数。

torch.export.export 用示例输入捕获计算图，随后转为 Edge 表示、交给 XNNPACK 做适配和降低，最后写入 ExecuTorch 的 .pte 文件。这里示例输入固定 [1,1,H,W]，代码没有声明动态形状，不能假定任意 batch 或任意尺寸都能直接运行。官方流程见 ExecuTorch 导出文档。

输出类型与意义注意事项
y_pxfloat32 [1,2,W]模型输入分辨率下的坐标；返回原图需逆变换
scoreuint8 [1]实际是 argmax 类别索引，非概率或置信分数
导出成功与推理等价是两件事

质量 checkpoint 路径硬编码在外部 Linux 目录，本项目目录未提供该外部文件。包装器标准化没有 epsilon，常量输入可能除零；还对整个张量取均值方差，与训练逐图处理的契约需核对。导出后只用随机输入执行并打印 shape/dtype，没有 PyTorch 与 PTE 输出误差对照，也没有真实数据集端侧准确率复测。文件夹里存在 .pte 文件不等于本次验证其可用。

这份代码没有固定版本的依赖清单，原始数据目录也指向 Linux 外部路径。先建立适合 PyTorch 的 Python 环境并记录 torch、torchvision、numpy、Pillow、opencv-python、batchgenerators、matplotlib、alive-progress、tabulate、mlflow 等版本；V4 额外需要 timm；端侧导出再加 ExecuTorch。以下为模板，路径必须换成自己的真实目录，未在本机执行训练。

闭卷综合题：解释一个 [4,2,256] 坐标张量怎样影响第一层卷积。

坐标损失对 ŷ 求梯度 → ŷ 是 softmax 概率的高度期望 → 概率来自上采样后的 logits → 插值和卷积将梯度传到热图头、融合层和骨干 → 回到最前面的可学习去噪卷积。topology/smoothness/TV 也经坐标路径反传；热图损失直接对 logits 产生另一条梯度路径，两者在共享参数处相加。
